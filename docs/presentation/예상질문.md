# 예상 질문 & 답변 (쉬운 버전)

> 답변 요령: 한 문장으로 결론부터 → 짧게 이유 설명. 모르면 맨 아래 만능 문장.

## 인프라

**Q1. Fargate라는 것도 있던데 왜 EC2를 썼나요?**
> Fargate는 "서버 관리까지 아마존이 다 해주는 대신 더 비싼" 옵션입니다.
> 우리 서버는 24시간 계속 켜져 있는데, 이런 경우엔 EC2가 더 쌉니다. 그리고 EC2를 직접 다뤄보는 게 학습 목적에도 맞았습니다.

**Q2. 게임 도중에 서버가 죽으면 게임이 날아가나요?**
> 안 날아갑니다. **게임 데이터(카드, 칩, 누구 차례인지)는 서버가 아니라 Redis라는 별도 저장소에 있어서**, 서버가 죽어도 데이터는 그대로예요.
> 죽은 서버는 자동으로 새 서버로 교체되고, 플레이어 화면은 자동 재접속해서 이어집니다.

**Q3. 그럼 Redis가 죽으면요?**
> 그건 맞는 지적입니다. 지금은 Redis가 1대뿐이라 거기가 죽으면 게임이 다 날아가요.
> 실제 서비스라면 Redis를 2대로 복제해서 하나가 죽으면 자동으로 교체되게 합니다. 이번엔 비용 때문에 1대로 했습니다.

**Q4. 서버가 여러 대인데, 4명이 다른 서버에 접속하면 어떻게 같은 게임을 하나요?**
> 모든 서버가 **같은 Redis를 보고 있기 때문**입니다.
> 비유하면 — 은행 창구(서버)는 여러 개지만 통장 원본(Redis)은 하나인 것과 같습니다. 어느 창구에 가도 같은 잔액이 보이죠.
> 그리고 "철수가 베팅했다" 같은 소식은 Redis의 방송 기능(Pub/Sub)으로 모든 서버에 전파됩니다.

**Q5. 두 명이 동시에 버튼을 누르면 꼬이지 않나요?**
> 안 꼬이게 만들었습니다. Redis에 "확인하고 → 저장하기"를 **한 번에 처리해달라**고 맡기는 방식(Lua 스크립트)을 써서, 중간에 다른 요청이 끼어들 수 없습니다.
> 화장실 문을 잠그고 들어가는 것과 같아요 — 안에 있는 동안 다른 사람이 못 들어옵니다.

**Q6. 왜 https가 아니라 http인가요?**
> 실습 범위라서 생략했습니다. 붙이려면 AWS에서 무료 인증서를 받아서 ALB에 설정만 추가하면 되고, 구조를 바꿀 필요는 없습니다.

**Q7. 비용을 더 줄일 방법은요?**
> 세 가지가 있습니다. ① 안 쓸 때 서버 끄기 (실제로 밤마다 0대로 줄였습니다) ② 스팟 인스턴스 — 아마존의 남는 서버를 싸게 빌리는 것 ③ 더 싼 종류의 서버(ARM 기반)로 바꾸기.

**Q8. 배포는 어떻게 하나요? 서비스 멈추고 하나요?**
> 안 멈춥니다. 새 버전 서버를 먼저 띄우고 → 정상 동작 확인되면 → 옛 버전을 내리는 "롤링 배포" 방식이라, 사용자는 배포 중인지도 모릅니다. 실제로 발표 준비 중에 버그 수정을 무중단으로 배포했습니다.

**Q9. 사람이 많아지면 어떻게 되나요?**
> 자동으로 늘어납니다. 서버가 바빠지면(CPU 70% 초과) 컨테이너가 자동으로 늘고, 컨테이너 들어갈 자리가 부족하면 EC2 컴퓨터 자체도 자동으로 늘어납니다. 반대로 한가해지면 자동으로 줄어요.

**Q10. 모니터링은요?**
> 서버 로그는 CloudWatch에 자동 수집되고, "에러가 갑자기 많아지면" / "서버가 아프면" 울리는 알람 2개를 설정해뒀습니다.

## 게임

**Q11. 해킹해서 상대방 카드를 볼 수 있지 않나요?**
> 못 봅니다. 상대 카드는 **애초에 내 컴퓨터로 전송되지 않아요.** 서버가 각자에게 자기 카드만 보내줍니다. 받은 적 없는 데이터는 해킹해도 볼 수 없습니다.

**Q12. 게임 몇 개까지 동시에 돌릴 수 있나요?**
> 게임 하나의 데이터가 아주 작아서(몇 KB) 수천 개도 문제없습니다. 한계가 오면 위에서 말한 자동 확장이 서버를 늘려줍니다.

**Q13. 테스트는 어떻게 했나요?**
> 3단계로 했습니다. ① 게임 규칙(족보 판정, 베팅)을 검사하는 자동 테스트 50개 ② 로봇 브라우저 4개가 진짜로 게임 한 판을 자동으로 플레이하는 테스트 ③ 마지막으로 실제 배포된 AWS 환경에서도 같은 테스트로 풀 게임 완주 확인.

**Q14. 만들면서 제일 어려웠던 버그는?**
> 20초 안에 행동 안 하면 자동으로 폴드되는 타이머가 있는데, 이게 **영원히 작동하지 않는 버그**가 있었습니다.
> 원인은 "마감 시각 메모"를 마감 시각이 되는 순간 자동으로 찢어버리도록 설정해놔서, 타이머가 확인하러 갔을 땐 메모가 이미 사라져 있던 거였어요. 메모를 조금 더 오래 보관하게 한 줄 고쳐서 해결했습니다.
